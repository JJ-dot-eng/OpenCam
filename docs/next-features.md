## 1. 지금 빠진 부분과 자주 겪을 불편

코드를 보고 확인한 사실 위주로 적었다.

| # | 불편 | 지금 상태 (근거) |

| 1 | **작업이 날아갈 수 있다.** 프로그램이 죽거나 PC가 꺼지면 녹화·편집한 것이 모두 사라진다. 나중에 이어서 편집할 방법도 없다(GIF로 저장하면 화질이 줄고 편집 기록도 없음). | 프레임은 메모리(`project.rs`의 `frames`)에만 있다. 프로젝트 파일 저장·자동 저장 없음 |

| 8 | **넓은 모니터에서 미리보기가 작다.** 위 툴바 + 아래 썸네일 줄이 세로 공간을 먹는다. | TODO의 "나중에 생각: 왼쪽 세로 목록, 아이콘 한 줄 툴바" |

| 10 | **화면이 한국어뿐이다.** GitHub에 공개했지만 해외 사용자는 쓰기 어렵다. | README에 "The UI is in Korean" |
| 11 | **소리가 없다.** MP4로 저장해도 소리를 담을 수 없다. | 설정에 "MP4로 바로 저장 (소리 없음)" |

## 2. 새 기능 후보 (11개)

난이도: 쉬움(하루 안팎) / 보통(며칠) / 어려움(일주일 이상 또는 위험이 큼).

### A. 작업 자동 저장·복구
- **무엇**: 편집 중인 프레임을 몇 초마다 디스크에 저장해 두고, 비정상 종료 뒤 다시 켜면 "복구할까요?"라고 묻는다.
- **누구에게 왜**: 모든 사용자. 긴 녹화를 공들여 편집하다 한 번 날리면 프로그램 신뢰가 무너진다.
- **난이도**: 보통~어려움. Rust(`project.rs`, `frame.rs`, 새 `recovery.rs`, `lib.rs`) + 프론트(시작 화면, 설정).
- **위험**: 디스크 사용량, 저장하는 동안 편집이 버벅임, 쓰다 끊겨 파일이 깨짐, 화면 내용이 디스크에 남는 개인정보 문제.

### B. 다시 실행 (Ctrl+Y / Ctrl+Shift+Z)
- **무엇**: 되돌린 작업을 다시 살린다.
- **누구에게 왜**: 모든 편집 사용자. 다른 편집 프로그램에서 당연히 있는 기능이라 없으면 바로 불편을 느낀다.
- **난이도**: 쉬움. Rust(`project.rs`에 redo 스택) + 프론트(`Editor.tsx` 버튼·단축키).
- **위험**: 메모리가 조금 늘어남(프레임 목록 복사본, 픽셀은 공유), 새 파일 열기·처음 상태로 등에서 기록 비우는 규칙을 빠뜨리기 쉬움.

### C. 목표 용량에 맞춰 저장
- **무엇**: "10MB 이하로"처럼 크기를 정하면 화질·FPS·이미지 크기를 알아서 낮춰 그 안에 맞춘다.
- **누구에게 왜**: GIF를 메신저·커뮤니티·이슈 트래커에 올리는 사람. 업로드 제한은 GIF 프로그램을 쓰는 가장 흔한 이유다.
- **난이도**: 보통. Rust(`export.rs`에 탐색 반복) + 프론트(`SaveDialog.tsx`).
- **위험**: 여러 번 인코딩해야 해서 느릴 수 있음, 아무리 낮춰도 못 맞추는 경우의 안내.

### D. 저장한 파일을 클립보드에 복사
- **무엇**: 저장 뒤 "파일 복사" 버튼(또는 설정 "저장하면 자동 복사"). 메신저·탐색기에서 Ctrl+V로 바로 붙여 넣는다.
- **누구에게 왜**: 짧은 GIF를 자주 공유하는 사람. 탐색기를 열 필요가 없다.
- **난이도**: 쉬움. Rust(Windows 파일 목록 클립보드 형식) + 프론트(`SaveDialog.tsx` 저장 뒤 화면).
- **위험**: 어떤 앱은 파일 대신 첫 프레임 그림만 받아 움직이지 않는다 → "파일 붙여 넣기를 지원하는 앱에서만"이라고 안내.

### E. 녹화 시작 카운트다운 (3·2·1)
- **무엇**: 녹화를 누르면 0~5초(설정) 세고 시작한다.
- **누구에게 왜**: 단축키·버튼 누르는 모습이 앞에 찍히는 게 싫은 모든 녹화 사용자.
- **난이도**: 쉬움. 프론트(`Recorder.tsx`) + Rust(시작 시점 지연, `recorder.rs`).
- **위험**: 숫자를 녹화 구멍 안에 그리면 그것도 찍힌다 → 툴바 안에 표시하거나 캡처에서 빠지는 창에 띄운다(돋보기 창과 같은 방식).

### F. 키 입력 표시
- **무엇**: 녹화 중 누른 키(예: `Ctrl + C`)를 화면 아래에 말풍선처럼 보여 준다. 녹화 때 기록만 하고 편집 창에서 삽입 레이어로 넣으면 나중에 위치·모양을 고칠 수 있다.
- **누구에게 왜**: 사용법·튜토리얼 GIF를 만드는 사람.
- **난이도**: 어려움. Rust(전역 키보드 후킹, 녹화 시각 기록) + 프론트(삽입 레이어 자동 생성).
- **위험**: **비밀번호 같은 입력이 영상에 남을 수 있다** → 기본 꺼짐, 글자 키는 빼고 단축키 조합만 표시하는 옵션. 키보드 후킹은 백신이 의심할 수 있음.

### G. 클릭 따라 자동 줌
- **무엇**: 녹화 중 클릭한 위치·시각을 기억해 두고, 줌 도구에서 "클릭 위치로 자동 만들기"를 누르면 그 자리를 확대하는 줌 구간을 만들어 준다.
- **누구에게 왜**: 넓은 화면을 찍은 뒤 작게 저장하는 사람. 작은 GIF에서도 무엇을 눌렀는지 보인다.
- **난이도**: 어려움. Rust(클릭은 이미 클릭 효과용으로 감지 중, 기록만 추가) + 프론트(`ZoomView.tsx`).
- **위험**: 프레임을 지우거나 합치면 클릭 시각과 프레임이 어긋난다, 줌이 너무 잦으면 어지럽다(가까운 클릭은 한 구간으로 묶기).

### H. 편집 창 배치 옵션 (왼쪽 세로 썸네일 / 아이콘 한 줄 툴바)
- **무엇**: TODO "나중에 생각" 항목. 썸네일 목록을 왼쪽 세로로, 툴바를 아이콘만 있는 한 줄로 바꿀 수 있게 한다.
- **누구에게 왜**: 넓은 모니터·노트북 사용자. 미리보기가 커진다.
- **난이도**: 보통. 프론트만(`Editor.tsx`, `FrameStrip.tsx`, `editor.css`).
- **위험**: 배치 두 가지를 계속 함께 유지·확인해야 함, 오른쪽 도구 패널이 열리면 미리보기 폭이 좁아짐.

### I. 시작 화면과 최근 파일
- **무엇**: 켰을 때 빈 미리보기 대신 "새 녹화 / 열기 / 최근 파일 5개(썸네일)"를 보여 준다.
- **누구에게 왜**: 저장한 GIF를 다시 고치려는 사람. A(복구)의 "복구할 작업" 자리도 여기에 둔다.
- **난이도**: 쉬움~보통. Rust(`settings.rs`에 최근 목록) + 프론트(`Editor.tsx` 빈 화면).
- **위험**: 지워진 파일 처리, 목록에 남는 파일 이름(개인정보) → "목록 지우기".

### J. 영어 화면 (다국어)
- **무엇**: 설정에서 한국어/English를 고른다.
- **누구에게 왜**: GitHub로 들어오는 해외 사용자. 공개 프로그램의 사용자 수를 가장 크게 늘릴 수 있다.
- **난이도**: 어려움(양이 많음). 프론트 모든 화면 글자 + Rust 오류 메시지.
- **위험**: 글자 수백 개, 영어가 길어져 좁은 툴바 배치가 깨짐, 새 기능마다 번역을 같이 해야 함.

### K. 소리 녹음 (MP4·WebM)
- **무엇**: 시스템 소리·마이크를 함께 녹음해 영상에 넣는다.
- **누구에게 왜**: 짧은 영상 클립을 만드는 사람.
- **난이도**: 어려움. Rust(Windows 소리 캡처 + ffmpeg로 합치기).
- **위험**: 이 프로그램은 프레임을 지우고 옮기는 편집이 중심이라 소리와 맞추기가 매우 어렵다. "MP4로 바로 저장" 모드에만 넣는 것이 현실적.

## 4. 상위 3개 자세히

### 4-1. 작업 자동 저장·복구 (A)

**동작 규칙**
- **저장 위치**: `%LOCALAPPDATA%\OpenCam\recovery\<작업 시작 시각>\`. 작업마다 폴더 하나. README의 "저장 위치"에 한 줄 추가.
- **언제**
  - 녹화가 끝나 편집 창에 프레임이 들어온 직후, 파일을 연 직후.
  - 편집(되돌리기 기록을 남기는 모든 작업) 뒤 5초 동안 다른 편집이 없으면.
  - 재생 중·도구 실행 중에는 미룬다.
- **무엇을**
  - 프레임마다 이미 압축된 데이터를 `frames/<프레임 번호>.lz4`로 **한 번만** 쓴다. 프레임 번호(`Frame::id`)는 픽셀이 바뀌면 새로 받으므로, 이미 있는 파일은 다시 쓰지 않는다. 지연시간만 바뀐 프레임은 목록 파일만 바뀐다.
  - 목록 파일 `manifest.json`: 프레임 순서, 번호, 가로·세로, 지연시간, 원래 파일 이름·저장 경로, 마지막 저장 시각, 프로그램 버전.
  - 목록 파일은 임시 이름으로 다 쓴 뒤 이름을 바꿔치기한다(쓰다 끊겨도 이전 목록이 살아 있음). 그다음 목록에 없는 프레임 파일을 지운다.
  - **되돌리기 기록은 저장하지 않는다**(용량). 복구한 작업은 되돌리기 기록 없이 시작한다고 알린다.
- **지우는 때**: 저장하고 닫음 / "저장하지 않고 닫기"를 고름 / 복구 화면에서 "버리기". 저장한 뒤 계속 편집 중이면 남겨 둔다.
- **켤 때**: recovery 폴더에 작업이 있으면 복구를 묻는다(프로그램은 한 개만 실행되므로 남아 있는 폴더 = 비정상 종료). 최근 3개까지만 보여 주고 나머지는 오래된 순으로 지운다.
- **디스크 보호**: 남은 공간이 1GB 미만이면 자동 저장을 멈추고 정보 줄에 "자동 저장 멈춤(디스크 공간 부족)"을 띄운다.
- **설정**: 일반 → "작업 자동 저장 (비정상 종료 시 복구)" 기본 켬. 설명에 "녹화 화면이 PC에 임시로 남습니다. 정상 종료하면 지웁니다".
- **MP4 바로 저장**에서 메모리 한도를 넘어 편집용 프레임을 버린 경우에는 자동 저장도 하지 않는다.
- **나중에 넓힐 수 있음**: 같은 형식을 `.ocam` 프로젝트 파일로 "저장/열기"하면 화질 손실 없이 다음 날 이어서 편집할 수 있다.

**복구를 묻는 화면 — 배치 비교**

안 1: 켤 때 가운데 대화상자
```
┌──────────── 편집 창 ────────────┐
│      ┌─────────────────────┐     │
│      │ 저장하지 못한 작업    │     │
│      │ [썸네일] 120장 8.3초  │     │
│      │ 어제 오후 3:12        │     │
│      │ [복구] [버리기] [나중에]│    │
│      └─────────────────────┘     │
└─────────────────────────────────┘
```
- 좋은 점: 절대 놓치지 않는다. 만들기 가장 쉽다(기존 `confirmAsk` 모양).
- 나쁜 점: 켤 때마다 길을 막는다. 여러 개면 대화상자가 커진다.

안 2: 시작 화면 안의 카드 (I와 같은 자리)
```
┌──────────── 편집 창 ────────────┐
│ [툴바]                           │
│   ● 새 녹화    📂 열기           │
│   ─ 복구할 작업 ─────────────    │
│   [썸네일] 어제 3:12 120장 [복구][×]│
│   ─ 최근 파일 ───────────────    │
│   [썸][썸][썸][썸][썸]           │
└─────────────────────────────────┘
```
- 좋은 점: 막지 않는다. 최근 파일·새 녹화와 한 화면에 모여 자연스럽다. 여러 개여도 줄만 늘면 된다.
- 나쁜 점: 바로 녹화하거나 파일을 끌어 놓으면 카드를 못 보고 지나칠 수 있다 → 지우지 않고 다음에 다시 보여 준다.

안 3: 툴바 아래 알림 띠
```
┌──────────── 편집 창 ────────────┐
│ [툴바]                           │
│ ⚠ 저장하지 못한 작업 1개 [열기][버리기][×]│
│ [미리보기]                       │
└─────────────────────────────────┘
```
- 좋은 점: 다른 작업 중에도 보인다. 편집 화면 배치를 거의 안 바꾼다.
- 나쁜 점: 이미 다른 작업을 열어 둔 상태에서 "열기"를 누르면 지금 작업을 어떻게 할지 또 물어야 한다.

**추천: 안 2.** 시작 화면(I)을 함께 만들면 이후 기능의 출발점이 된다. 처음에는 최근 파일 없이 "새 녹화 / 열기 / 복구할 작업"만 있어도 된다.

### 4-2. 다시 실행 (B)

**동작 규칙**
- 되돌리기를 하면 지금 상태를 "다시 실행 기록"에 넣는다. 다시 실행하면 거꾸로.
- **새 편집을 하면 다시 실행 기록을 비운다**(일반 편집 프로그램과 같음).
- "처음 상태로"도 하나의 편집으로 다뤄 되돌리기·다시 실행 대상에 넣는다(지금 되돌릴 수 있는지 구현 때 확인).
- 새 녹화·파일 열기·새로 만들기를 하면 두 기록 모두 비운다.
- 단축키: Ctrl+Y, Ctrl+Shift+Z. README 단축키 표에 추가.
- 최대 단계는 되돌리기와 같이 50. 정보 줄의 메모리 표시(`Project::memory_bytes`)에 다시 실행 기록도 포함.
- 도구 패널에 적용하지 않은 변경이 있을 때 다시 실행을 누르면, 지금처럼 "버릴까요?"를 먼저 묻는다.

**버튼 배치 비교**

안 1: 되돌리기 옆 버튼 하나
```
[↶ 되돌리기][↷ 다시 실행][⟲ 처음 상태로]
```
- 가장 단순. 툴바 "되돌리기" 묶음에 버튼 하나만 는다.

안 2: 버튼 + 기록 목록 펼치기
```
[↶][↷][▾]
      ┌────────────────────┐
      │ ✓ 필터: 흑백         │
      │   프레임 12장 삭제    │
      │   자르기 640×360     │
      │   (녹화 직후)         │
      └────────────────────┘
```
- 여러 단계를 한 번에 오갈 수 있다. 각 작업에 이름을 붙여야 한다(Rust의 기록 지점마다 이름 저장).

안 3: 왼쪽 도구 목록에 "작업 기록" 도구 → 오른쪽 패널
```
[도구] │ [미리보기]          │ 작업 기록
 ...   │                     │ ▸ 필터: 흑백   [썸]
 기록  │                     │   12장 삭제    [썸]
       │                     │   녹화 직후    [썸]
```
- 시점마다 썸네일까지 보여 줄 수 있다. 가장 크고 오른쪽 패널을 차지한다.

**추천: 안 1로 먼저 내고, 기록마다 이름은 지금 같이 저장한다.** 그러면 버튼에 마우스를 올렸을 때 "되돌리기: 필터 적용"처럼 보여 줄 수 있고, 나중에 안 2로 넓히기 쉽다.

### 4-3. 목표 용량에 맞춰 저장 (C)

**동작 규칙**
- 목표 크기(MB)를 정하면 저장 버튼이 "맞춰서 저장"으로 바뀐다. 빠른 값 단추: 5 / 10 / 25 / 50MB, 직접 입력.
- **GIF·WebP·APNG**: 아래 순서로 하나씩 낮춰 본다. 사용자가 "건드리지 말 것"에 체크한 항목은 건너뛴다.
  1. 화질: 지금 값에서 50까지
  2. FPS 제한: 지금 FPS → 20 → 15 → 10
  3. 이미지 크기: 100% → 90% → … → 50%
  - 단계마다 반씩 좁혀 가며 찾는다(이분 탐색).
- **빠르게 재기**: 전체를 매번 저장하지 않고, 고르게 뽑은 일부 프레임(전체의 약 1/5)만 인코딩해 비율로 전체 크기를 짐작한다. 마지막에 실제로 저장해 보고 목표를 넘으면 한 단계 더 낮춰 다시 저장한다.
- **여유**: 목표의 95% 안을 노린다.
- **MP4·WebM**: 목표 크기 ÷ 길이로 비트레이트를 계산해 ffmpeg에 바로 넘긴다(반복 탐색 없음).
- **진행 표시**: "3번째 시도 — 화질 70, 15 FPS, 90% → 예상 9.4MB" + 취소.
- **못 맞출 때**: 다 낮춰도 크면 가장 작게 만든 결과의 크기를 보여 주고 "구간을 줄이거나 크기를 더 낮추세요"라고 안내. 그래도 저장할지 묻는다.
- **결과**: 실제로 쓴 설정을 보여 준다(편집 중인 프레임은 그대로). "다음에도 이 목표 크기 쓰기"는 설정에 기억.
- 60 FPS GIF 경고(50 FPS로 맞추기)는 지금처럼 먼저 처리하고 나서 용량 맞추기를 시작한다.

**저장 창 배치 비교**

안 1: 화질 줄에서 "화질로 / 용량으로" 전환
```
형식  [GIF ▾]
기준  (● 화질로) (○ 용량으로)
화질  ━━━━━●━━━ 80              ← 화질로
목표  [10] MB  [5][10][25][50]   ← 용량으로
      줄여도 되는 것: ☑화질 ☑FPS ☐크기
[예상 크기 계산]           [저장]
```
- 좋은 점: 화질 막대와 목표 용량이 같은 자리라 "둘 중 하나로 정한다"는 게 바로 보인다.
- 나쁜 점: 저장 창의 화질 줄 모양이 형식마다 달라져 손볼 곳이 많다.

안 2: 맨 위 형식 옆에 "목표 크기" 드롭다운
```
형식 [GIF ▾]   목표 크기 [없음 ▾ / 5MB / 10MB / 25MB / 직접]
화질  ━━━━━●━━━ (자동)   ← 회색으로 잠김
파일 크기 줄이기 (자동)
[저장]
```
- 좋은 점: 저장 창 위쪽에서 가장 먼저 정한다. 기존 칸을 거의 안 바꾼다.
- 나쁜 점: 아래 칸들이 잠긴 이유를 알아차리기 어렵다. "건드리지 말 것"을 고를 자리가 없다.

안 3: 저장 뒤 결과 화면에서 "줄여서 다시 저장"
```
저장했습니다  my.gif  18.2MB
[폴더 열기] [편집으로] [줄여서 다시 저장 ▸ [10]MB]
```
- 좋은 점: 저장 창을 하나도 안 바꾼다. 크기를 보고 나서 결정한다.
- 나쁜 점: 처음부터 목표가 정해진 사람은 두 번 저장해야 한다.

**추천: 안 1.** 목표가 있는 사람은 처음부터 고르고, 화질만 보는 사람은 지금과 똑같이 쓴다. 안 3의 "줄여서 다시 저장"은 나중에 덧붙이기 쉽다.
